# 文档、运行输出与本机材料的边界

从[文档导航](README.md)进入当前使用说明。以下路径是仓库相对路径，不依赖某位协作者的电脑目录、服务或推理设备。

## 各目录负责什么

| 路径 | 职责与事实来源 | 进入 Git 的内容 |
|---|---|---|
| `docs/` | 当前操作、架构/契约、规划及脱敏历史结论 | 团队共同维护的知识、必要的脱敏配图与来源许可 |
| `docs/reports/` | 某一日期、源码和设备条件下实际发生的事 | 结论、失败、验收边界、来源版本与证据标识；不代表当前全局状态 |
| `docs/archive/` | 已被后续实现或新交接替代的方案与旧 handoff | 保留来源与指向当前入口；不再作为开发待办 |
| `docs/course/source/` | 迁移时保存的原始课程说明与许可 | 原文保持不变，旧命令不作为当前入口；血缘见迁移清单 |
| `outputs/` | 每次程序运行的可变输出，包括训练/评估结果 | 只提交根 README；原始日志、媒体和结果留本机 |
| `local_artifacts/validation/`、`experiments/` | 被选为证据的原始运行结果、失败回合和测量记录 | 全部忽略；通过 manifest 记录来源路径、执行类别、时间与校验值 |
| `local_artifacts/history/`、`worktree-archives/` | 旧源码、工作区资料及迁移回执 | 全部忽略；不当作新的源码或模型入口 |
| `local_artifacts/tmp/<任务>/` | 短期草稿、审查中间数据 | 全部忽略；结束后把需要保留的记录归档 |
| `deliverables/assignment-NN/YYYY-MM-DD-rNN/` | 固定作业报告、视频、源码快照和提交包 | 只追踪根与每项作业的 README；payload 不提交 |
| `data/`、`checkpoints/` | 数据集、模型与配套 manifest/处理器资产 | 原始数据和权重忽略，不能为清理日志而搬动它们 |
| `.venv/`、`environments/training/.venv/` | 控制与训练两套有效环境 | 可重建但在用时保留，不复制到每个验证目录 |

共享配置模板、程序契约和标定仍在各自代码/配置目录，不复制到 docs 或 outputs。个人串口、相机、API Key 与认证文件保持本机隔离；模型、框架、自有服务、第三方 API 的区别见[推理边界](inference_boundaries.md)。

## 来源与删除判断

血缘至少区分：原始输入 → 源码/配置/模型版本 → 生成命令与执行条件 → 原始输出 → 验收结论 → 固定成品。Git 提交历史能证明文件何时进入仓库，不能证明本机输出由哪个提交生成；文件修改时间也不能填补这个缺口。

完全重复须逐文件比较 SHA-256。相同文件若分别承担课程来源、许可、固定版本证据与当前指南职责，仍可合理并存。相似段落需要核对范围、单位、日期与验收类别，不能自动合并。未被链接的文档可能只是缺导航。

迁移记录保存源/目标相对路径、字节数、SHA-256、保留理由与操作结果；先复制、校验，再删除有完整归档且无人使用的源副本。唯一内容、失败实验、旧提交成品、许可或血缘不完整的文件默认保留，标注缺口。清理不重新认证旧测试，也不重新解释为成功。

## 文档和成品修订

当前操作命令只在其责任指南维护，架构文件维护边界，规划维护未完成目标；日期报告保留当时状态，发现错误时追加更正与后继入口。旧 handoff 退役时转入 archive，并在原路径保留短入口，避免现有链接断裂。不要复制第二份“最新交接”。

作业格式见[成品指南](../deliverables/README.md)。定版 payload 不跟着主线升级重打；修正时创建新日期/修订，注明原源码与提交回执。新实验目录推荐 `YYYY-MM-DD_HHMMSS_<主题>`，实际执行类别写在 manifest，不靠文件名推断。

一般任务使用当前仓库的临时分支；仅在确需隔离时建立受 Git 管理的临时 worktree，并记录用途。不要在项目父目录或系统临时目录堆放长期克隆、虚拟环境、报告与提交包；测试可用自动清理的 TemporaryDirectory。工作区删除与分支合并/CI 条件仍遵守 CONTRIBUTING。

CI 会拒绝被追踪的 outputs 结果或 deliverables payload。指南可协作维护，个人数据和凭据不会随之上传。本轮逐项审查见[血缘报告](reports/2026-10-24-artifact-lineage.md)。

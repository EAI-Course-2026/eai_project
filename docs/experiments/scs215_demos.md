# 六关节固定起点演示 v3

在项目根目录运行；本台设备使用本机配置指定的串口。夹爪空载，机械臂固定/支撑，周围无遮挡，退出后继续支撑，因为会关闭全部扭矩。

## 选择演示

| 版本 | 动作 | 执行 |
|---|---|---|
| home | 只进入统一演示起点 | `uv run --no-sync python scripts/arm_demo.py --demo home --enable` |
| gripper | 保持臂姿，夹爪两端往返两次 | `uv run --no-sync python scripts/arm_demo.py --demo gripper --enable` |
| showcase | 底座左右、腕部转向、明显夹爪变化 | `uv run --no-sync python scripts/arm_demo.py --demo showcase --enable` |
| transfer | A 侧探出、模拟夹持、收回转运、B 侧释放 | `uv run --no-sync python scripts/arm_demo.py --demo transfer --enable` |

每个版本都先执行相同的归位动作；三个动作版最后返回同一起点。`transfer` 是空载关节姿态编排，没有物体识别、末端坐标或接触检测，不能把它当成自动抓取。加 `--backend lerobot` 使用 LeRobot SCS215 适配版；默认 serial 版只依赖 pyserial。

去掉 `--enable` 是只读预览。每个动作默认停留 1.2 秒，拍摄可以加 `--hold 2`；`Ctrl+C` 停止并尝试关闭全部扭矩。每个版本的默认日志是 `outputs/assignment2/demo_<版本>_latest.json`，可用 `--log` 另存，避免覆盖旧记录。旧版 `--amplitude` 已移除。

## 固定起点和初始误差

保存的起点是原始刻度 `[360,174,664,162,789,420]`，顺序为底座、肩、肘、腕俯仰、腕旋转、夹爪。不是六个机械中点，不能用全 0.5 代替。

1. 读取六台型号、ID、位置、硬件限位；检查校准文件和起点文件完全匹配。
2. 检查当前位置属于下表的软件接纳范围，状态无报警、六关节扭矩关闭。
3. 先保持底座、腕旋转和夹爪在测得的位置，调整肩、肘、腕俯仰到固定起点。
4. 再调整底座、腕旋转、夹爪；六关节到位后才开始所选 demo。

| 关节 | 固定起点 | 软件允许起始反馈 |
|---|---:|---:|
| shoulder_pan | 360 | 180..563 |
| shoulder_lift | 174 | 61..287 |
| elbow_flex | 664 | 551..772 |
| wrist_flex | 162 | 67..265 |
| wrist_roll | 789 | 566..1012 |
| gripper | 420 | 234..623 |

范围是起点 ± 配置半径与校准范围的交集，读取反馈时两处边界均容许 3 刻度漂移；例如 shoulder_lift 在重力下读到 63 时可归位，而 60 仍会被拒绝。容差只用于起始反馈，保持目标和后续运动目标仍受原校准范围约束。，是软件门限，不是整个盒内所有组合都经实物认证。目标始终在校准范围内；正式演示目标距端点至少 20 刻度。边界外的初始位置拒绝运动，支撑并关闭扭矩后手动移入范围。六个位置反馈不能判断连杆是否互撞或是否被外物卡住，所以不承诺任意初始姿态无碰撞归位。

可离线模拟不同起点，确认归位后动作相同：

```sh
uv run --no-sync python scripts/arm_demo.py --demo showcase --anchor-raw 349 81 771 93 813 278
uv run --no-sync python scripts/arm_demo.py --demo showcase --anchor-raw 480 192 652 180 920 590
```

## 分段推进和卡顿处理

六个目标同帧发送。按当前位置到该阶段目标的固定直线分段，每次最多推进 20 刻度。中间段必须达到 25 刻度以内的跟随误差才推进，阶段最终目标须达到 `--tolerance`（默认 15，最高 15）才报告到位。关节静态误差可能使逐小段要求 15 刻度卡住，因此中间跟随门限与最终验收分开；作业的 `arm_serial.py` / `arm_lerobot.py control` 默认仍为 10 刻度。

每段检查状态；位置无效、越界、状态报警或子段等待 8 秒超时即停止，不自动反复推向被卡的位置。日志记录阶段、子段、目标、反馈、误差和退出扭矩状态。遇到卡住先停止并查看记录，不通过放宽最终容差或扩大目标强行通过。

夹爪目标端 A 为 590、端 B 为 280，跨度 310 刻度，是原演示的约三倍。标签不假定哪个方向是张开，实际开口与装配有关；这些目标不包含机械端点，也没有夹紧力反馈。只用于空载展示。

## 重新示教共同起点

当前起点只适用于本台机械臂与附带校准，不自动移植到其他机器。需要换一个适合取景的起点时，支撑并关闭扭矩，手动摆好一次，再只读采集：

```sh
uv run --no-sync python scripts/arm_serial.py release
uv run --no-sync python scripts/arm_demo.py --teach-home configs/my_demo_home.local.json
uv run --no-sync python scripts/arm_demo.py --home-file configs/my_demo_home.local.json --demo showcase
uv run --no-sync python scripts/arm_demo.py --home-file configs/my_demo_home.local.json --demo showcase --enable
```

示教不会开启扭矩或改写 EEPROM，不覆盖已有文件；保存前检查三个版本的全部目标都能落在内缩限位内，不自动裁剪改变动作。若提示夹爪偏移越界，将示教夹爪放在约 420 刻度附近再采集；其他关节也需给演示偏移留足空间。`start_radius_counts` 可收窄接受误差；扩大半径需要相应实物验证，不因此获得避碰保证。

## 实物验证记录

新版在已有充电宝供电下继续验证。首次固定起点归位成功，起始 `[349,81,771,93,812,278]`，终点反馈 `[356,170,677,159,791,411]`，最大误差 13，退出六台扭矩均为 0，见 `v3_home_serial.json`。

保留随后失败回合 `v3_gripper_serial.json`：归位途中肘目标 734、反馈 750，16 刻度误差超过当时逐小段的 15 刻度要求而停止；未开始夹爪动作。此证据促使中间跟随门限改为 25、最终到位保持 15；不是将失败记录改成成功。

夹爪版修正后完整通过 `v3_gripper_serial_retry.json`：两个开合回合、返回共同起点均达到 15 刻度，夹爪阶段反馈 288..582（跨度 294）。退出六台扭矩均为 0。

左右展示第一次 `v3_showcase_serial.json` 在第六段肘目标 652、反馈 668（16 刻度）停止。最终版本保持肩肘腕俯仰在共同起点，底座、腕旋转和夹爪负责明显展示。`v3_showcase_serial_retry.json` 全部通过 15 刻度；从另一组初始位置 `[479,187,712,173,671,282]` 归位，第二段反馈 `[367,175,666,165,781,413]` 最大误差 8。该版底座反馈 249..473、腕旋转 677..906，夹爪 288..582，退出扭矩均为 0。

这证明本次测得的不同起点可收敛，不代表入口范围内所有姿态组合都已测试。39 项离线测试通过，额外覆盖中间 16 刻度静态误差可以继续、最终 16 刻度仍失败且不会伪报 15 刻度到位。失败时优先记录关闭扭矩前的反馈，避免释放后姿态下落混淆诊断。

LeRobot 后端空载搬运版 `v3_transfer_lerobot.json` 完整通过 11 段（含两段共同归位和返回起点），所有阶段最大误差不超过 15；结束反馈 `[365,171,665,159,792,429]` 最大误差 9。随后独立串口只读检查确认六台 torque=0、status=0、约 4.9V、19–20°C。三个动作版本分别有实物通过记录；并未穷举每个动作与每个后端的组合。

v3 提交包附本台校准与起点，内置当前串口配置。换电脑或端口时加 `--port 实际串口`；换机械臂应重新校准和示教，不沿用本台参数。拍视频推荐 `showcase --hold 2`，它的主体姿态较稳定，底座、腕旋转和夹爪变化清楚。

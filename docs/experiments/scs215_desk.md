# SO101 六关节本机上位机

在项目根目录启动：

```sh
uv run --locked python scripts/arm_desk.py
```

启动器只在 `127.0.0.1` 提供界面并自动打开浏览器，打开页面不会连接或移动舵机。若电脑没有自动打开浏览器，终端会显示可访问的本机 URL。默认使用 `configs/hardware.local.toml` 中的串口，也能在界面中改；可加 `--device-port SERIAL_PORT`，其中 `SERIAL_PORT` 要替换为本机设备名（Windows 如 `COM5`）。可加 `--no-open` 只打印地址。退出终端用 `Ctrl+C`；程序会尝试关闭扭矩和串口。

## 操作顺序

1. 支撑机械臂、确认空载且周围无遮挡。填写串口，选择原生串口或 LeRobot 后端，点“连接机械臂”。连接时只读验证六台 ID、型号、硬件限位与状态。
2. 点“进入统一起点”。程序读取当前六关节刻度、检查是否在 `configs/demo_home.json` 的入口范围内，分段归位；确认到位后才开放滑杆。每条目标是六舵机同步写入。
3. 归位入口对六关节实测反馈允许 3 刻度边界漂移（包括重力使 shoulder_lift 从 64 落到 63）；下发目标仍限制在校准范围内。六个滑杆使用校准后的 0–1 数值，界面显示本机当前允许输入的子范围。目标位于内缩 20 刻度与演示入口范围的交集，超过这一范围会在发命令前拒绝。拖动时不会立刻运动；点“发送六关节目标”才执行。当前反馈、电压、温度、扭矩与状态定期刷新。可用“目标 ← 当前反馈”撤销待发送编辑。
4. 也可选夹爪开合、左右展示或空载转运。每个演示都会先重新确认统一起点，再运行动作，最后返回起点。
5. “停止 / 释放扭矩”可在运动中请求停止；运动线程在下一次串口反馈或目标写入前响应，并逐台关闭扭矩。若浏览器失去连接超过 8 秒，独立看门狗也会请求停止。页面关闭时额外尝试发停止请求。扭矩释放后需继续支撑机械臂。切断电源是串口失联时的实体应急方式。

运动保持上次设备速度设置，不修改 EEPROM、PID 或舵机编号。每个子段最多推进 20 刻度，中间跟随容许 25 刻度，最终到位容差 15 刻度，单子段超时 8 秒；归位范围和演示路径不构成碰撞规划。原作业命令行双版本仍可独立运行，默认到位容差 10 刻度。

## 校准工作台

连接后可查看当前六关节硬件范围、方向与反馈。停止并支撑机械臂后，手动将各关节放在希望输入 0 和 1 对应的两个安全端点，分别点击采集；采集只读取位置。12 个端点齐全且每关节相距至少 20 刻度后，可以另存软件校准 JSON 与来源说明，不覆盖现有文件，也不写入舵机 EEPROM。

新校准不会自动取代当前运行中的文件。要使用它，用 `--calibration 新文件路径` 重新启动上位机。旧起点与新校准不匹配时，界面只允许只读连接和示教；先支撑并关闭扭矩，手动摆好与新范围相容的姿态，点“只读采集当前姿态为新起点”。界面会立即启用新起点，后续启动可同时指定 `--calibration` 与显示的新 `--home-file`。起点示教会预检三个演示版本的所有目标，避免另存无法执行的起点。

## 当前验证

当前 56 项离线测试通过，其中上位机测试覆盖只读连接、归位门禁、超范围输入拒绝、运动中停止并释放六台扭矩、浏览器心跳丢失自动停止、校准另存以及仅本机 HTTP 接口。浏览器中也实际检查了页面、六滑杆和三个演示按钮，模拟六台舵机做了连接、归位、滑杆发送与演示中停止交互。

早期一次检查中本机串口设备文件暂时不存在，因此那一轮 GUI 检查只完成模拟联调；后来已录制网页上位机发出命令后机械臂运动的实物演示，视频及复现说明在本地 `assignment2_handin/`，该目录不纳入 Git。底层双后端与三个固定起点 demo 的实物记录见 `docs/experiments/scs215_demos.md`。

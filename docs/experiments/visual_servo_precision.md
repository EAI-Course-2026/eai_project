# 下一轮：精细视觉伺服

状态：实验计划，尚未在真机执行。当前可复现基线是2026-10-18中央区域MVP，不直接
缩小死区或把固定步长模式标为精密控制。下一次启动须重新摆稳与预检；卸扭矩后的姿态
已经改变，本轮临时hold-reference/resume-response不能作为新实验的接管授权。

## 1. 先补齐可测量的输入和执行记录

记录每帧四角点、中心、图像尺寸、原始/去畸变坐标、PnP位姿、相机单调时间戳；
同时记录关节反馈时间、目标计数、实测计数、到位/部分响应和丢帧状态。
建立wall-clock与monotonic的对应关系，便于与操作者视频对齐。保持仅一个可见窗口，
画出目标区域/角点以及真实的运行/等待/暂停原因。

本轮`control_hz`参数不代表实测调度频率。先测端到端时延、采样抖动和静止目标角点噪声，
再选择真实执行频率；不要在未测延迟时宣称高频连续伺服。

## 2. 执行响应按轴、方向、姿态/负载建模

已有证据：手腕12计数请求的实际运动中位数，正向13、反向6；底座10计数请求中位实际7。
因此图像矩阵应作用于“期望实际关节变化”，再经过有边界的响应补偿得到请求，而非假设
请求等于反馈。保留编码器量化、反向背隙、静摩擦、200ms稳定判定和真实到位区分。

优先离线重放已有27步数据，再在固定标记下做少量针对性的方向/反转验证。
不重新做大范围盲扫，不写EEPROM/PID，不让执行容差覆盖整个动作。
估计目标自身运动时，不直接更新机械臂图像响应矩阵；静止标定阶段与动态跟随阶段分开。

## 3. 核对标定链路后接入五轴IBVS

- 相机：现有640×480内参，平均重投影0.355px、RMS 0.408px；确认分辨率与安装。
- 末端：操作者已确认`gripper_frame_link`和相机安装未变。
- 手眼：`gripper_T_camera`平移约(21.47,17.79,-61.43)mm；不把矩阵合法、距离合理当成物理精度验收。
- 标定板：内参文件记录棋盘格19.6mm，而任务描述为25mm；需和协作者确认实物/计算尺度，保留原始文件。
  ArUco外边长25mm是独立的操作者测量值。
- FK：数值实现和约30cm高度粗验通过，但物理零点、方向、比例尚不能只靠数学一致性保证。

内参主点约(346,211)，与画面几何中心(320,240)不同；四角点目标取自明确的可达参考姿态，不能混淆光心与几何中心。

先只读验证角点顺序、去畸变、PnP尺度与`base_T_gripper @ gripper_T_camera`约定，
再复用现有`joint_adapter.py`的相机雅可比和`aruco_ibvs.py`的图像雅可比。
机器人只有五个运动关节；四角点误差不能被当作任意八个独立可达约束，需检查雅可比秩、
阻尼与可达目标。目标角点宜先来自一个实际可达并保存的相机姿态，避免强迫不可达目标。

## 4. 分级验收

| 阶段 | 目标 | 必须同时记录 |
|---|---|---|
| 静止输入 | 测量角点与PnP抖动基线 | 每帧时间、角点、关节反馈；不启用动作 |
| 中心细化 | 先验证中心误差≤10px的可达性 | 实际动作、方向响应、残差、稳态抖动 |
| 四角点 | 可达性确认后，试验RMS≤5px、稳定1s | 8维角点误差、尺度/方向、Jacobian秩、预算与失效事件 |
| 动态跟随 | 至少10次移出目标区域并重新收敛 | 逐帧误差、端到端延迟、真实完成时间、丢失恢复与停止原因 |

这些是候选验收目标，不是已实现精度；关节分辨率、摩擦或标定误差若使目标不可达，
先报告实测下限，再调整控制或验收。只在本轮明确的空间、限位和停止机制内试验。
自动前进和任意物体跟随分别验收，不随中心/四角点收敛自动宣布完成。

# SCS215 安全工作范围候选（尚未启用）

机械可达、EEPROM 命令限位、软件 0–1 工作范围、演示入口和目标到位容差是不同约束。本候选以用户确认的机械可达刻度和实机 EEPROM 回读为依据。绝大多数端点内缩 20 刻度；ID3 上端距 EEPROM 上限 10 刻度。关节 2 的 EEPROM 最小值仍为 64；候选输入 0 对应 84。**可达不等于动力验证或组合避碰验证。**

候选文件：`calibration/scs215_safe_candidate_20260928.json`。配套起点文件：`configs/demo_home_scs215_safe_candidate_20260928.json`，两者需成对使用。默认 `calibration/scs215_so101.json` 和已运行上位机未切换到候选。

离线校验：四种 demo 的全部固定目标在候选范围上即使再内缩 20 刻度，仍在可命令区间。腕旋转候选跨度为 969 刻度，命令行控制仍需显式 `--allow-wide-range`；这一离线通过不证明靠近 0/1023 的反馈连续性。

`ArmController.recover_startup()` 已实现与普通 `enable()` 分离的启动回收：先检查六台型号、ID、EEPROM 限位、状态、扭矩和初始反馈；在 EEPROM 邻域保持当前姿态，可选先抬腕与调夹爪离桌，再逐步回到软件范围。失败时关闭六台扭矩。普通 `enable()` 和 `move()` 保持严格软件范围检查。`scripts/arm_verify_candidate.py` 默认只读，只有 `--enable` 才运动；`--manual-start` 只跳过固定 demo 入口，仍执行 EEPROM 邻域、回收距离和状态检查。

`scripts/arm_set_id3_limit.py --enable` 已把 ID3 EEPROM 上限由 769 改为 771。写前六台扭矩和状态均为 0、ID3 EEPROM 锁为 1；写后和重新打开串口后回读均为 771，锁恢复为 1，其他五台限位未变。**断电重上电后的持久性尚未回读。**

实物日志在 `outputs/assignment2/candidate_*.jsonl`。关节 2 候选低端目标 84 得到反馈 98，误差 14。夹爪两端目标 260、618 分别得到反馈 269、610，并完成往返。用户指出夹爪曾碰桌；抬腕至 330、夹爪至 520 后，关节 2 高端附近目标 697、反馈 683，误差 14；目标 717 未通过。经用户手动支撑，另一回合的关节 2 到目标 697、反馈 684；继续时 ID3 无法保持 664，触发连续 1.5 秒无进展停机。回程也出现过 ID2 目标 562、反馈 579 无进展停机。所有失败回合最终六台扭矩均为 0。

无扭矩时 ID3 多次被重力带回 771–772；该位置是用户确认可达，不等于候选软件目标。抬腕至 330 后，其启动回收曾停在目标 746、反馈 765，尚不能保证从该重力姿态自动回收。**完整六轴候选范围、关节 2 高端以及任意起点避碰都未验收通过，不应激活候选作为默认。**当前 GUI 与 demo 会在软件范围上再加运行余量，切换前还需统一 0–1 的含义，避免重复内缩。

# 项目定位、硬件边界与任务质量

2026-10-19。长期目标：人通过自然语言（含语音）提出机械臂控制任务，系统理解意图、
获取观测、选择能力、执行任务，并根据反馈判断结果。任务交互与执行是共同产品边界。

## 多模块共同优化

语音是输入方式，视觉提供观测，模型与规则提供决策和控制，harness 组织上下文、
工具与任务生命周期。训练是可选优化手段；当前重点可以是现成模型的选择、提示词、
模型/技能路由、观测策略、工具协议、反馈控制与任务评测。

研发保持[两条主线](development_workstreams.md)：模型与规则控制、学习感知与决策。
二者组合完成任务。云端/端侧是独立的部署维度，不能据此拆成长期源码分支。
模型路由选择推理资源，技能路由选择执行方法；两者都不能发放运动权限。

例：“对准这个目标并保持”失败，可能来自指代错误、检测漂移、旧观测、技能选错、
控制误差或腕部行程耗尽。先测任务结果，再用时序和反馈定位模块；模型输出流畅不代表完成。

## 硬件能力边界必须显式表达

可完成任务取决于关节自由度/行程、姿态、负载、保持误差、回差、速度、相机视野与反馈质量。
边界可能随姿态、负载和环境变化；不能把配置上限或单次成功等同于已测可用工作空间。
已有承重保持误差与腕旋行程不足的证据见[伺服报告](reports/2026-10-19-servo-feedback-guards.md)。

能力描述应区分：

| 来源 | 记录方式 | 不能推导的结论 |
|---|---|---|
| 设备/模型声明 | 型号、自由度、坐标/单位、文档或模型版本 | 不代表本机精度、负载、避碰或全行程已验证 |
| 本机配置/标定 | 共享范围、标定摘要、当前技能参数 | 不等于所有姿态都可达或能稳定保持 |
| 实测证据 | 设备、姿态、负载、环境、日期、误差与失败日志 | 不外推到未测条件 |
| 当次执行授权 | 本机模式、活动任务、运动租期与操作者授权 | 模型或会话记忆不能扩大授权 |

系统只能从当前能力与证据中选择技能；条件不满足时调整任务、请求澄清/人工介入或拒绝。
未知数值保持 unknown/null，不能由 LLM 补齐。prompt 和 harness 检查不替代本地执行器写前检查。
当前运行模块只提供 dry-run 能力声明，负载、真实工作空间与精度均未在其中虚构数值。

## 评测围绕任务，而非只看模块分数

建立固定任务、输入/场景、独立成功判据和预算，保存版本、配置、观测/调用/发送/反馈时序。
初始任务族可包括命名姿态、相对末端移动、目标对齐、持续跟随；各自单独定义误差、持续时间、
失败条件和人工标签。在实物验收前，仿真/干跑不能填入实物成功率。

| 测试分层 | 评价内容 |
|---|---|
| 已测能力内 | 任务成功率、到位误差、完成时间、人工干预、模型调用与资源成本 |
| 接近能力边界 | 姿态/负载等条件变化时如何退化，能否识别限制并及时停止 |
| 已知超出能力 | 是否正确拒绝/调整，是否如实说明未完成 |
| 尚未测量 | 记录 unknown，安排测量，不自动归为模型失败或硬件不可达 |

失败分类至少保留：语言理解、目标定位、路由/计划、控制/跟随、观测时序、硬件边界、
提供方/通信、取消、未知；允许一个事件涉及多个模块。保留所有试验及失败，不能删除失败后算成功率。
没有成功标签时保持未标注；“停止成功”与“原任务完成”分别计分。

迭代闭环为：固定任务集 → 建立基线 → 测量结果 → 定位失败 → 修改模块 → 相同条件回归比较。
按实验分别修改 prompt、模型、路由、harness 或控制参数；必要时再做组合实验，识别相互影响。
大型训练不是前置条件，小规模适配是否值得做由任务失败证据决定。

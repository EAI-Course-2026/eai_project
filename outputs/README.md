# 运行输出

`outputs/` 是程序生成结果的落点，不是操作文档、原始数据集、模型仓库或固定提交成品。这里只追踪本指南；日志、JSON、图像、音视频、训练结果和凭据均不提交 Git。

新运行优先使用 `outputs/<功能>/YYYY-MM-DD_HHMMSS_<主题>/`；在已有 CLI 支持的 `--output` / `--output-dir` 中传入。已有命令的默认路径仍有效，本轮不改变执行行为。运行前确认目标不会覆盖要保留的旧证据；没有防覆盖能力的入口由操作者选择新目录。

## 一个结果的生命周期

1. 运行时写到独立输出目录，记录源码提交、配置/标定与模型摘要、输入来源、执行类型（模拟、真实 API、只读、实物、GPU）。不要记录密钥。
2. 验收结束后，值得保留的原始结果和失败证据归入本机 `local_artifacts/validation/<日期-任务>/` 或 `experiments/`，保存来源路径与 SHA-256；固定交付另归 `deliverables/`。
3. 将可公开的结论整理进 `docs/reports/`，链接对应版本及证据标识；不要把整份运行日志贴成长期指南。
4. 确认可重建或有完整归档后才删除输出副本。未引用、名称相似或日期久远均不是删除依据；有唯一材料、来源不明或仍被配置引用时保留。

凭据只放会话内存、环境变量或被忽略的本机配置；不把服务认证文件当作验收附件归档或上传。

本轮血缘与保留决定见[审查报告](../docs/reports/2026-10-24-artifact-lineage.md)，整体边界见[工作区规则](../docs/workspace.md)。
